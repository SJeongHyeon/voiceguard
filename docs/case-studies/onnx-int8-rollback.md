# 사례 연구: ONNX INT8 분류기를 도입했다가 점수 포화로 PyTorch로 되돌린 일

**결정: 임시 롤백 · 원인은 확정하지 못함**

보이스가드는 통화를 잘게 나눈 청크마다 KoELECTRA 분류기가 보이스피싱 의심 점수를 계산합니다. PR #57이 이 분류기를 ONNX INT8 런타임으로 연결했습니다. 동기는 CPU 추론 시간과 배포 환경의 메모리를 줄이는 것이었고, 성능 결론은 범위 밖으로 두었습니다([`docs/specs/onnx-int8-classifier.md`](../specs/onnx-int8-classifier.md)).

## 무엇을 했나

- 서버가 시작할 때 Whisper STT와 PyTorch KoELECTRA 분류기를 한 번씩 불러오도록 되돌렸고, 기존 API 응답 계약은 바꾸지 않았습니다.
- 목표는 같은 입력으로 PyTorch와 ONNX 두 런타임의 점수를 **비교할 수 있는 상태**를 만드는 것이었습니다.
- 범위 밖으로 둔 것: 임계값·점수 보정 변경, ONNX 파일 삭제, 재학습, STT 변경.

## 쓰지 않은 것(기록이 없어서)

- **원인**: 확정하지 못했습니다. 스펙은 원인을 확인하기 위한 임시 롤백이라고만 적었고, 양자화가 원인인지는 저장소에 기록이 없습니다.
- **해결 여부**: 두 런타임의 비교 결과 기록을 저장소에서 찾지 못했습니다. 롤백으로 포화가 해결됐다고 적을 근거가 없습니다.
- **도입 동기의 달성 여부**: 시간·메모리 절감이 실제로 얼마였는지 측정한 기록이 없습니다.
